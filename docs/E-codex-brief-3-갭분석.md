# Codex 브리프 #3 — E 인수인계·휴직 심층 갭 분석 (분석 전용)

> ⏳ **설계 시점 스냅샷 (2026-08-06 보존)** — 이 문서는 E 모듈 설계·기획 과정의 기록이며 최종 구현이 아니다. 예외 정책·상태 enum·응답 필드·경계식 등 실제 계약은 그 뒤 `develop` 코드에서 확정됐다. **정본은 항상 `develop`의 코드**이며, 문서와 코드가 다르면 코드가 옳다.

> **분석 전용. 코드 절대 수정 금지.** 산출물만: `docs/E-갭분석-결과.md` 1개 파일 작성.

## 목적
E(인수인계·휴직·퇴사) + 퇴사 패키지 + 토큰 미터링 설계에서 **우리가 빼먹었거나 정의 안 된 논리적 구멍(엣지케이스·미규정 규칙·상태 충돌)**을 심층 분석해 리스트업. 개발 들어가기 전에 규정돼 있어야 편한 것들.

- 실제 구현 코드: `src/main/java/com/module06/backend/handover/**`, 테스트 3종

## 출력 포맷 (사용자 지정 — 예시와 동일하게)
각 갭마다 정확히 이 3요소:
1. **시나리오/예시** — 구체적 상황(사람·업무·수치로)
2. **문제** — 왜 막히나/왜 모호한가 (버그·데드락·미정의)
3. **정할 것** — 결정해야 할 선택지(옵션 나열, 가능하면 권장안)

> 참고 — 이미 해소된 2개(이 포맷의 본보기, 다시 리스트업 하지 말 것):
> - 퇴사자 완료 업무 → 진행중 프로젝트 전체 포함, 완료는 기록용(reassignRequired=false)
> - 팀장/host 공석 → 새팀장=오너 지정, host 회의=퇴사 시 삭제, 팀장퇴사=오너가 다른팀장 수동인계

## 분석 관점 (이 카테고리별로 구멍 찾을 것 — 예시는 힌트, 더 찾아낼 것)
1. **상태머신·생애주기**: 반려 후 재신청? 이미 인수인계 진행 중 재신청(중복 handover)? 휴직 중 퇴사(ON_LEAVE→OFFBOARDING)? 작성자 본인 신청 취소? 최종승인 전 후임이 그 액션을 이미 완료?
2. **비동기 레이스**: handover 생성 후 AI 파이프라인이 새 액션을 나가는 사람한테 자동 배정(고아)? 요약 PROCESSING 중 퇴사?
3. **재분배 대상**: 팀원이 본인밖에 없어 후임 없음? 후임 지정자도 곧 나감/휴직중? 인계할 액션 0개? 후임이 그 액션 프로젝트에 권한 없음?
4. **스냅샷·데이터 정합**: handover 생성 후 프로젝트 상태 변경(진행중→완료)? source meeting 삭제 시 §5 조회 dangling? 후임/작성자 이름 변경(스냅샷이라 OK인지 확인)?
5. **권한·역할**: 오너 본인 퇴사(누가 최종승인)? ADMIN 퇴사(인수인계 미노출인데)? 팀장 퇴사 시 오너가 다른팀장 인계=권한/UI 경로?
6. **동시성**: 두 관리자 동시 최종승인/반려? 팀장 완료와 오너 최종승인 경합?
7. **오프보딩 완결성**: host 회의 삭제 시 그 회의서 나온 액션의 source_meeting_id dangling? 삭제된 회원이 다른 handover의 후임으로 지정돼 있으면?
8. **토큰 미터링**: 요약 FAILED 시 토큰? 재분석 시 이전 실패분? 월 경계 걸친 회의 귀속? 쿼터 초과 시 진행중 요약? 부서 이동/삭제 시 사용량 귀속? 기업 탈퇴 시 기록?
